An archive service stores identifier strings in a prefix structure.

Identifier strings can be efficiently stored as a data structure, to have efficient searching methods.
A new archive service is going to use this method, but they don't have much space. So they want to check beforehand how much memory will be required for their data. 
Following method describes the way in which this archive service's catalogers save the data in the structure.

Suppose they have 5 identifier strings/identifier words: et,eq,bd,be,bdp
A empty node is kept NULL, and identifier strings are inserted into the structure one by one. 
Initially the structure is this:

NULL

After inserting "et", the structure is this:

NULL
 |
 e
 |
 t

After inserting "eq", the structure is this:

   NULL
   /
  e
 / \
t   q

After inserting "bd", the structure is this:

   NULL
   /  \
  e    b
 / \    \
t   q    d

After inserting "be", the structure is this:

     NULL
   /     \
  e       b
 / \     / \
t   q   e   d

After inserting "bdp", the structure is this:

    NULL
   /     \
  e       b
 / \     / \
t   q   e   d
             \
              p

Therefore a total of 8 nodes are used here.    

Input: 
First line contains N, the number of identifier strings they have.  
Each of the next N lines contain one identifier string. Each identifier string consists only of lowercase letters.    

Output: 
Print the required number of nodes.    

**Constraints: 
1 ≤ N ≤ 10^5     
Length of each identifier string  ≤ 30    

Note: No two identifier strings are same, though one identifier string could be prefix of another.

SAMPLE INPUT
5
et
eq
bd
be
bdp

SAMPLE OUTPUT
8
