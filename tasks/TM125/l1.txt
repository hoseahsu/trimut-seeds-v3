A designer records attempts and completions of a trial course.

Marek has recently created a new trial course in this cool new simulator Trial Builder 85 and uploaded it online. Now participants from all over the world can try his trial course.

All trial courses in this simulator have two stats to them: the number of attempts and the number of completions. So when a participant attempts the trial course, the number of attempts increases by 1. If he manages to finish the trial course successfully then the number of completions increases by 1 as well. Note that both of the statistics update at the same time (so if the participant finishes the trial course successfully then the number of attempts will increase at the same time as the number of completions).

Marek is very excited about his trial course, so he keeps peeking at the stats to know how hard his trial course turns out to be.

So he peeked at the stats n times and wrote down n pairs of integers — (p_1, c_1), (p_2, c_2), ..., (p_n, c_n), where p_i is the number of attempts at the i-th moment of time and c_i is the number of completions at the same moment of time. The stats are given in chronological order (i.e. the order of given pairs is exactly the same as Marek has written down).

Between two consecutive moments of time Marek peeked at the stats many participants (but possibly zero) could attempt the trial course.

Finally, Marek wonders if he hasn't messed up any records and all the pairs are correct. If there could exist such a sequence of attempts (and completions, respectively) that the stats were exactly as Marek has written down, then he considers his records correct.

Help him to check the correctness of his records.

For your convenience you have to answer multiple independent test cases.

Input

The first line contains a single integer T (1 ≤ T ≤ 500) — the number of test cases.

The first line of each test case contains a single integer n (1 ≤ n ≤ 100) — the number of moments of time Marek peeked at the stats.

Each of the next n lines contains two integers p_i and c_i (0 ≤ p_i, c_i ≤ 1000) — the number of attempts and the number of completions of the trial course at the i-th moment of time.

Note that the stats are given in chronological order.

Output

For each test case print a single line.

If there could exist such a sequence of attempts (and completions, respectively) that the stats were exactly as Marek has written down, then print "YES".

Otherwise, print "NO".

You can print each letter in any case (upper or lower).

Note

In the first test case at the third moment of time the number of completions increased but the number of attempts did not, that couldn't have happened.

The second test case is a nice example of a Super Expert trial course.

In the third test case the number of attempts decreased, which is impossible.

The fourth test case is probably an auto trial course with a single jump over the spike.

In the fifth test case the number of completions decreased, which is also impossible.

Nobody wanted to play the sixth test case; Marek's mom attempted it to make him feel better, however, she couldn't clear it.
