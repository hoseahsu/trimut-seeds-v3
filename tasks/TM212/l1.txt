An operator tracks unread alerts from terminal modules.

Marek is getting used to the Arden. As a gift Nolan gave him a terminal. There are n modules on this terminal. Marek is fascinated by this terminal. He has only one minor issue: he can't count the number of unread alerts generated by those modules (maybe Nolan put a curse on it so he can't).

q events are about to happen (in chronological order). They are of three types:

  1. Module x generates a alert (this new alert is unread). 
  2. Marek reads all alerts generated so far by module x (he may re-read some alerts). 
  3. Marek reads the first t alerts generated by terminal modules (alerts generated in first t events of the first type). It's guaranteed that there were at least t events of the first type before this event. Please note that he doesn't read first t unread alerts, he just reads the very first t alerts generated on his terminal and he may re-read some of them in this operation. 



Please help Marek and tell him the number of unread alerts after each event. You may assume that initially there are no alerts in the terminal.

Input

The first line of input contains two integers n and q (1 ≤ n, q ≤ 300 000) — the number of modules and the number of events to happen.

The next q lines contain the events. The i-th of these lines starts with an integer typei — type of the i-th event. If typei = 1 or typei = 2 then it is followed by an integer xi. Otherwise it is followed by an integer ti (1 ≤ typei ≤ 3, 1 ≤ xi ≤ n, 1 ≤ ti ≤ q).

Output

Print the number of unread alerts after each event.

Examples

Input

3 4
1 3
1 1
1 2
2 3


Output

1
2
3
2


Input

4 6
1 2
1 4
1 2
3 3
1 3
1 3


Output

1
2
3
0
1
2

Note

In the first sample:

  1. Module 3 generates a alert (there is 1 unread alert). 
  2. Module 1 generates a alert (there are 2 unread alerts). 
  3. Module 2 generates a alert (there are 3 unread alerts). 
  4. Marek reads the alert generated by module 3, there are 2 unread alerts left. 



In the second sample test:

  1. Module 2 generates a alert (there is 1 unread alert). 
  2. Module 4 generates a alert (there are 2 unread alerts). 
  3. Module 2 generates a alert (there are 3 unread alerts). 
  4. Marek reads first three alerts and since there are only three of them so far, there will be no unread alert left. 
  5. Module 3 generates a alert (there is 1 unread alert). 
  6. Module 3 generates a alert (there are 2 unread alerts).
